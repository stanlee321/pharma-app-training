# Design System & Build

Two loosely related concerns that both live outside the feature code: the centralized styling primitives in `PharmaApp/Utilities/DesignSystem.swift`, and how the Xcode project is produced from `project.yml` via XcodeGen. See [[architecture]] for the overall layout and [[state-navigation]] for where these tokens get consumed.

## Design System

Everything visual is centralized in `PharmaApp/Utilities/DesignSystem.swift` so the curve/compartment color meanings stay consistent across the hand-drawn chart ([[simulation-screen]]) and the compartmental animation ([[compartmental-screen]]). The file is four small namespaced enums/extensions — no instances, all `static`. Reuse these rather than introducing ad-hoc colors/fonts.

### AppColors

`enum AppColors` (a namespace of `static let Color` values). The app is designed dark-first — surfaces assume a black background.

**Curve palette** (the semantic core; these meanings are load-bearing and reused everywhere):

| Symbol | Hex | Meaning |
|---|---|---|
| `plasma` | `#00D4FF` cyan | plasma concentration Cp curve |
| `effect` | `#4ADE80` green | effect-site Ce curve |
| `infusion` | `#FB923C` orange | infusion rate |
| `target` | `#3B82F6` blue | target concentration marker |
| `targetDashed` | `#3B82F6` @ 0.4 opacity | dashed target guide line |

Note `targetDashed` is just `target` at `.opacity(0.4)`, computed inline in the declaration.

**Compartment fluid colors** (used by the 2D/3D compartment views to tint each glass compartment's fluid):

| Symbol | Hex | Role |
|---|---|---|
| `v1Fluid` | `#EF4444` red | central compartment V1 fluid |
| `v2Fluid` | `#22D3EE` cyan | peripheral V2 fluid |
| `v3Fluid` | `#14B8A6` teal | deep peripheral V3 fluid |
| `effectFill` | `#4ADE80` green | effect-site fill (same RGB as `effect`, declared separately) |
| `clearance` | `#6B7280` gray | clearance/elimination |

Gotcha: `v2Fluid` (#22D3EE cyan) is a *different* cyan from the curve `plasma` (#00D4FF). The compartment palette is its own scheme keyed by compartment index (V1/V2/V3), not by the Cp/Ce/infusion curve semantics — don't assume "cyan means plasma" inside the compartment views.

**UI surfaces:** `darkBg` (`Color.black`), `darkCard` (`#1C1C1E`), plus chart chrome `gridLine` (white @0.12), `gridLineMajor` (white @0.2), and `axisText` (white @0.6). Colors are defined with `Color(red:green:blue:)` in the 0–1 sRGB space; the `//` hex comments are the authoring reference.

### Font extensions

`extension Font` adds six named text styles. Most are aliases onto the Dynamic-Type system styles (so they scale with accessibility settings), two are fixed:

- `drugTitle` = `.title2.bold()`, `modelName` = `.title3`, `sectionHeader` = `.headline` — semantic Dynamic-Type roles.
- `numericValue` = `.system(.body, design: .monospaced).bold()` — monospaced so digits don't jitter as readouts update live during target drag.
- `axisLabel` = `.system(size: 10, design: .monospaced)` — a **fixed 10pt** monospaced size (does not scale with Dynamic Type), for chart axis ticks.
- `tinyLabel` = `.caption2`.

### Haptics

`enum Haptics` wraps UIKit feedback generators in three semantic calls. Each constructs a fresh generator per call (no cached/prepared instance):

- `tap()` → `UIImpactFeedbackGenerator(style: .light)` — general button/stepper taps. Used broadly, e.g. `StepperRow`, `CompartmentalView`, `DrugSelectionView`, `PatientInputView`.
- `targetSnap()` → `UIImpactFeedbackGenerator(style: .medium)` — fired when the dragged target snaps to a new value (`SimulationView` compares `snapped != prevSnapped`).
- `confirm()` → `UINotificationFeedbackGenerator().notificationOccurred(.success)` — commit actions (drug confirmed, patient confirmed).

These call `UIImpactFeedbackGenerator` directly, so the file imports UIKit transitively via SwiftUI and is iOS-only.

### Spacing

`enum Spacing` — four `CGFloat` constants: `screen: 16`, `section: 20`, `item: 12`, `tight: 4`. Padding/stack-spacing scale for the whole app.

## Build

### XcodeGen generates the project from `project.yml`

`PharmaApp.xcodeproj` is a **build artifact**, not source — it is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. Never hand-edit the `.xcodeproj`; edits are overwritten on the next generate. The workflow (per `CLAUDE.md`):

```bash
xcodegen generate          # regenerate the .xcodeproj from project.yml
open PharmaApp.xcodeproj    # select a team in Signing, pick a device/sim, Cmd+R
```

**Critical gotcha:** sources are picked up by directory scan, not enumerated in `project.yml`. `targets.PharmaApp.sources` is just `path: PharmaApp`. So after **adding, renaming, or moving any `.swift` file you must re-run `xcodegen generate`** — otherwise the new/renamed file is not in the target and won't compile in. This is the single most common "why isn't my file building" trap in this repo.

### `project.yml` specifics

- **Target:** one application target `PharmaApp`, iOS platform.
- **Deployment target: iOS 17.0** (`options.deploymentTarget.iOS`), Xcode 16.0. iOS 17 is what enables the `@Observable` / `.environment(...)` observation model used throughout (see [[state-navigation]]).
- **Sources:** whole `PharmaApp/` tree, **excluding `Resources/MockData`** from compilation.
- **Resources:** `PharmaApp/Resources` bundling `*.json`, `*.xcassets`, and `MockData/*.json`. So `MockData/*.json` is *excluded as source but included as a bundled resource* — those are the pre-computed simulation snapshots the app loads at runtime (see [[engine]]).
- **Bundle:** `PRODUCT_BUNDLE_IDENTIFIER: com.pharma.tivatrainer` (prefix `com.pharma`), display name **TivaTrainer**, `MARKETING_VERSION 1.0.0`, `CURRENT_PROJECT_VERSION 1`.
- **Info.plist is generated** (`GENERATE_INFOPLIST_FILE: true`) — orientation, launch screen, and display name are set as `INFOPLIST_KEY_*` build settings, not a checked-in plist. All four orientations are allowed.
- **App icon:** `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon`. (`TODO.md` lists the actual icon art as outstanding.)

### `SWIFT_STRICT_CONCURRENCY: complete`

Set in `project.yml` base settings. This is why concurrency annotations are pervasive across the codebase: model/output types are `Sendable`, engine implementations are `@unchecked Sendable`, and UI state (`AppState`, view models) is `@MainActor`. New engine-crossing types must be `Sendable` and new UI state must respect main-actor isolation, or the build fails. See [[architecture]] and [[engine]].

### No tests, no lint

There is **no test target and no lint config** in this repo — confirmed: no `.swiftlint.yml`/`.swiftformat`, no `*Tests*` files, and `project.yml` declares only the one app target with no test target and no XCUITest scheme. The hand-calculated expected values in `docs/reference/rust-engine-spec/04_Validation_Reference.md` are reference-only and are **not** wired into an XCTest suite (relevant to [[pk-engine-math]]). Do not claim tests pass — there are none to run.

### Regenerating mock data

Two separate generators exist (see [[engine]]):
- `swift generate_mock_data.swift` — standalone script (PK types duplicated inline) that writes the 5 JSON snapshots into `PharmaApp/Resources/MockData/`.
- `PharmaApp/Engine/MockDataGenerator.swift` — the *in-app* equivalent using the real engine types. Keep the two scenario lists in sync if you change either.

### TestFlight

Bump `CURRENT_PROJECT_VERSION` in `project.yml` per upload → `xcodegen generate` → Xcode → Product → Archive → Distribute.

## Drift vs docs

- `CLAUDE.md` describes the curve color meanings as "cyan = plasma, green = effect, orange = infusion," which matches `AppColors.plasma/effect/infusion` in code. Note that "cyan" is overloaded: the *curve* cyan is `plasma` (#00D4FF) but the *compartment* palette also has a cyan `v2Fluid` (#22D3EE) meaning V2 fluid — these are distinct and not interchangeable.
- Consistent with the rest of the project's engine state: `EngineProvider.useMock` is `true` and `RustPKEngine` is a `fatalError()` stub (see [[engine]]). Nothing in the design-system/build layer changes that; the build config just enforces the `Sendable`/`@MainActor` contract that lets the engine be swapped later.
